# Skill 体检 skill-check

## 1. 一句话

装 Skill 之前先体检：清单、上下文、引用时效、已装冲突，四项全是代码算的，不靠猜。

在线演示：https://laomaiai.github.io/skill-check/

## 2. 它解决什么问题

Agent Skill 生态正在爆发，GitHub 上每天都有新 Skill。独立开发者装 Skill 之前只能凭感觉：清单写得对不对、装上要吃多少上下文、里面引用的命令和 API 是不是已经停用了、会不会和已装的 Skill 重名或抢触发，全靠人工一个一个看。

本工具把这四件事变成确定性检查：粘贴一个 Skill 的 GitHub 链接（或直接粘贴 SKILL.md），立刻得到四项分数、总分和一条一条的结论。NVIDIA 出了企业级重框架版 SkillEvaluator，独立开发者用不起；本工具是轻量免费版。

## 3. 输入来源与覆盖

三种输入，同一套检查：

1. 粘贴 GitHub 链接：支持仓库根目录、tree/blob 链接、raw.githubusercontent.com 链接和 owner/repo 简写。只取 SKILL.md 文件，需要联网。
2. 直接粘贴 SKILL.md 全文：离线可用。
3. 内置示例：三个示例 Skill（好的、中等的、差的），离线可用。

时效表：内置一张命令、安装包和 API 的时效表，核对日期 2026-11-17，共 30 条（命令 19 条、安装包 4 条、API 7 条）。不在表里的引用只报“未核实”，不算错。

## 4. 四项检查规则

总分 = 清单合规 x 0.30 + 上下文占用 x 0.25 + 引用时效 x 0.25 + 已装冲突 x 0.20，四舍五入取整。

### 4.1 清单合规（0-100）

- frontmatter 存在：25 分。
- name 存在且格式合规（小写字母、数字、短横线，不超过 64 字符）：25 分。
- description 存在且非空：25 分；长度 40 字以上且写清什么时候用：再加 15 分，否则加 5 分并提示。
- 没有未识别的 frontmatter 字段（只认 name、description、license、compatibility、metadata、allowed-tools）：10 分。

### 4.2 上下文占用（0-100）

token 估算 = SKILL.md 字符数 / 4（向上取整），并注明是估算值。

- 1000 tokens 以内：100 分；4000 以内：80 分；10000 以内：60 分；25000 以内：40 分；超过：20 分；空文件：0 分。
- SKILL.md 超过 500 行时提示（建议 500 行以内，细节移到引用文件），不另扣分。

### 4.3 引用时效（0-100）

从 100 分开始扣：

- 引用已停用的命令、安装包或 API：每条扣 25 分。
- 引用已改名的：每条扣 15 分。
- 引用需要留意的（例如 moment 进入维护模式、python 建议写 python3）：每条扣 5 分。
- 引用不在时效表里的安装包或 API 地址：每条扣 5 分，总共最多扣 20 分，只报“未核实”，不算错。
- 只引用当前版本的命令、包或 API：不扣分。
- 没有引用任何外部命令、包或 API：100 分，无时效风险。

### 4.4 已装冲突（0-100）

需要用户提供已装 Skill 列表（每行一个，格式是名字或“名字：描述”）：

- 与已装 Skill 重名：扣 40 分。
- 描述相似度达到 50% 以上（关键词 Jaccard 相似度）：每条扣 15 分。
- 名字是通用词（commit、review、test、deploy、docs、build、lint）：只提示，不扣分。
- 没提供已装列表：只做通用名检查，100 分并注明。
- Skill 缺少 name：无法检查，100 分并注明。

### 4.5 结论档位

- 90 分以上：可以直接装。
- 70-89 分：可用，先修小问题。
- 50-69 分：建议修改后再装。
- 50 分以下：不建议装。

### 4.6 示例分数（已装列表为空）

- 好的示例 pdf-tools：总分 100（清单 100、上下文 100、时效 100、冲突 100），可以直接装。
- 中等示例 video-helper：总分 85（清单 90、上下文 80、时效 70、冲突 100），可用，先修小问题。
- 差的示例 mega-tool：总分 46（清单 0、上下文 80、时效 25、冲突 100），不建议装。

### 4.7 真实 Skill 验证（2026-11-17）

拿 Anthropic 官方仓库 anthropics/skills 里的 6 个真实 Skill 跑了一遍（SKILL.md 从 raw.githubusercontent.com 现取，已装列表为空）：

| Skill | 总分 | 结论 |
| --- | --- | --- |
| pdf | 93 | 可以直接装 |
| docx | 93 | 可以直接装 |
| xlsx | 94 | 可以直接装 |
| pptx | 86 | 可用，先修小问题（SKILL.md 约 7043 tokens，偏重） |
| webapp-testing | 95 | 可以直接装 |
| skill-creator | 89 | 可用，先修小问题（SKILL.md 约 8247 tokens，偏重） |

没有误报：6 个官方 Skill 全部 86 分以上，没有一个被判“不建议装”；给出的提醒都是实话（例如都提示把 `python` 写成 `python3`、不在时效表里的包只报“未核实”不算错）。

## 5. 怎么用

1. 打开页面，选一种输入方式：粘贴 GitHub 链接、直接粘贴 SKILL.md、或点一个内置示例。
2. （可选）在“已装 Skill 列表”里填你已装的 Skill，每行一个，格式是名字或“名字：描述”；也可以点“填入示例已装列表”试试冲突检查。
3. 点体检，页面显示总分、结论档位和四项卡片，每条结论都带通过、注意、问题或说明标记。
4. 改了已装列表后请重新点一次体检。

## 6. 本地运行

```bash
npm install
npm test     # 跑 Vitest 测试
npm run build
npm run dev  # 本地开发
```

Node 20 以上。构建产物在 dist/。

## 7. 数据更新

时效表在 `src/lib/skillcheck.ts` 里的 FRESHNESS_TABLE，带核对日期 FRESHNESS_TABLE_CHECKED_AT。工具或 API 出了新大版本、停用通知时，在表里加一条并更新核对日期，再跑一遍测试。表里没有的引用不会被判错，只报“未核实”。

## 8. 确定性说明

- 本工具 100% 确定性，零大模型调用。同一份 SKILL.md 和同一份已装列表，每次跑出同一个分数（测试里有确定性用例）。
- token 数是估算值（字符数 / 4），页面和报告里都注明是估算。
- 粘贴的 SKILL.md 不上传到任何服务器；GitHub 链接只向 raw.githubusercontent.com 取文件。
- 哪些是代码算的：四项分数、总分、结论档位、引用匹配、冲突相似度，全是代码算的。大模型不参与任何环节。

## 9. 合规边界

- 不涉及股票、加密、资金托管。本工具只检查 Skill 文件本身，不执行、不安装、不调用任何 Skill。
- 不收集用户数据，不写 cookie，不调第三方统计。
- 引用链接只用于取 SKILL.md，不做其他请求。

## 10. 局限与下一步

- 时效表只有 33 条，覆盖的是常见命令、包和 API；冷门工具会报“未核实”，需要人工核对。表会随使用慢慢扩。
- 上下文占用是字符数估算，不是真实 tokenizer 计数；长中文内容估算偏保守。
- 冲突检查只看名字和描述相似度，不读 Skill 的正文指令；两个 Skill 正文撞指令的情况目前查不出来。
- GitHub 链接只取 SKILL.md 一个文件，不取它引用的其他文件；引用文件很多的 Skill，上下文占用会被低估。
- 下一步：扩时效表（加更多 CLI 和 API）；支持粘贴整个 Skill 目录打包检查；加真实 Skill 链接做验证用例（见 NOTES.md）。
